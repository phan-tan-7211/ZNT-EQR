# 역할 및 권한

ZNTEQR에는 두 가지 역할 계층이 있습니다. 조직 역할(소유자, 관리자, 구성원)과 팀 역할(매니저, 기술자, 요청자, 조회자)입니다. 각 역할을 누가 맡아야 하는지는 도움말 센터의 [팀 및 역할](/ko/support/teams-roles/)을 참조하세요.

### 재고 및 내부 원가 표시 범위

재고/부품 접근 권한은 두 가지 명시적 권한 부여(`organization_members.role` 값이
아님)인 **부품 관리자**와 **부품 사용자**를 통해 부여됩니다.
소유자와 관리자는 기본적으로 접근 권한을 가집니다. 작업 지시의 **비용
항목**(부품, 단가, 작업 시간/요율)은 내부 데이터입니다.
고객 대면 역할(팀 요청자 및 조회자)과 일반 구성원에게는 애플리케이션 어디에서도
부품, 재고 수준, 가격, 인건비에 대한 **어떠한 흔적도** 보여서는 안 됩니다.
내부 원가 계산과 최종 가격 책정은 이후
QuickBooks 청구 단계에서 처리됩니다.

**적용 계층:**

- **RLS.** `work_order_costs` 정책은 `can_access_work_order_costs(work_order_id, user_id)`를 사용합니다. 여기에는 조직 소유자/관리자, 작업 지시 담당자, 작업 지시가 속한 팀의 팀 소유자/매니저/기술자가 포함됩니다. 재고 테이블은 `can_access_inventory` / `can_manage_inventory`를 사용합니다.
- **애플리케이션.** `useCanViewWorkOrderCosts()`가 비용을 표시하는 모든 UI(비용 섹션, 카드 소계, 대시보드 비용 위젯, 메모의 작업 시간)를 제어합니다. `useInventoryAccess()`가 모든 재고 화면(라우트, 사이드바, 설비 부품 탭, 작업 지시 부품 선택기, 대시보드 FAB)을 제어합니다.
- **내보내기.** 고객용 서비스 보고서 PDF에는 관리자가 아닌 대상에게 비용/인건비가 절대 포함되지 않습니다. 일괄 내보내기는 조직 관리자만 가능합니다(edge `verifyOrgAdmin`).

두 권한 부여 모두 재고 페이지의 **부품 접근 권한** 패널에서(또는 조직 → 구성원에서 구성원별로) 관리합니다. 소유자/관리자만 두 역할을 부여하거나 회수할 수 있습니다.

### 치공구 관리 {#tooling-management}

**적용 계층:**

- **데이터베이스.** 치공구 이력 테이블은 클라이언트에 대해 읽기 전용입니다. 모든 변경은 SECURITY DEFINER RPC를 거치며, 이 RPC는 단계를 확인하고 공구 행을 잠근 뒤 같은 트랜잭션에서 이력을 기록합니다. 조직 간 연결은 복합 외래 키로 거부됩니다.
- **애플리케이션.** `useToolingPermissions()`가 데이터베이스에서 거부될 컨트롤을 숨깁니다.

### 감사 로그 표시 범위 (#1122)

조직 감사 로그는 모든 계층에서 **소유자와 관리자**로 제한됩니다. 페이지는 **조직 → 감사 로그** 아래에 있으며 페이지 내 역할 가드가 적용되고, `audit_log` SELECT RLS는 활성 소유자/관리자 멤버십을 요구하며, `get_audit_log_timeline` RPC가 `is_org_admin`을 다시 확인합니다. 감사 항목은 운영 페이지(작업 지시 또는 재고 상세)에 절대 표시되지 않으며, 전용 감사 CSV/JSON 내보내기 경로 외의 데이터 내보내기에는 절대 포함되지 않습니다. 이 전용 경로는 내보낼 때마다 관리자에게 알립니다.

### 테넌트 격리 규칙

- DSR 케이스는 `dsr_requests.organization_id`로 범위가 제한됩니다.
- 접근 검사는 edge function과 데이터베이스 정책 경계 양쪽에서 강제됩니다.
- 행위자의 조직 밖 요청은 `404`로 반환됩니다(조직 간 구분을 숨기는 방식).
- 같은 조직 내 역할에 의한 거부는 `403`으로 반환됩니다.
